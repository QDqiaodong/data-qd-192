# 本地复核工单 SLA 核算 v1

课程运营组用本命令离线核算本地复核工单的服务水平协议（SLA）：工单在两支助教队
之间交接，也可能因等待补件暂停；队伍的服务时段按周模板与日期替换给出，课程组
还会调整现有工单的时限。本命令查明**每张工单是否首次违约、在哪一分钟违约、
应记到哪支队**，同时给出完整累计分钟与按队违约计数。

只处理教学合成数字摘要、UTC 日期/时刻与业务编号：沿用 v1 数字摘要的五字段校验
与 single/light/heavy 档位（`fragments` 为 1、2–7、8 以上），不读取作业内容、源
字符串、片段内容或切分规则；不改动任何既有命令，运行只依赖 Python 标准库。

```sh
sequence-digest-sla --source SLA.json --output DIGEST.json
# 或无需安装：
PYTHONPATH=src python3 -P -m sequence_digest.sla_cli \
  --source SLA.json --output DIGEST.json
```

## 输入

顶层恰含 `as_of`、`teams`、`policies`、`tickets`。所有时刻是严格
`YYYY-MM-DDTHH:MMZ`（UTC 整分钟），日期是有效公历 `YYYY-MM-DD`；编号沿用仓库
ASCII ID 约定（`[A-Za-z0-9_:-]{1,64}`，区分大小写）。沿用严格 JSON 边界：8 MB、
拒绝重复键与非有限值、布尔值不作整数、多余字段拒绝。

### 助教队（`teams`，1–256 项）

每项恰含唯一 `team_id`、`weekly`、`overrides`。

- `weekly` 恰有七个数组，依次代表周一至周日；每个数组含 0–8 个 `[start,end]`
  时段，端点按当日自 00:00 起的整数分钟计，`0 ≤ start < end ≤ 1440`。时段不得
  重叠、**可以相邻**、不得跨日。
- `overrides` 至多 128 项，每项恰含 `day`、`windows`；日期在队内唯一，
  `windows` 格式同单日数组，**整体替换**当天的周模板；空数组表示当天不上班，
  因此日期替换优先于周表（包括「替换成停服」）。

### 策略（`policies`，1–8192 项）

每项恰含 `course_id`、`effective_at`、`limits`；前两项组合唯一。`limits` 恰含
`single/light/heavy`，各为 1–1051200 的整数有效分钟。

- 每张工单打开时必须已有该课程**不晚于开单时刻**的策略，否则拒绝输入。
- 同一课程总是采用不晚于当前时刻的最近一条；新策略也适用于未结工单，**不重置
  累计时间**。输入里允许存在开单时刻之后、甚至 `as_of` 之后的未来策略；整份
  输入都要通过校验。

### 工单（`tickets`，0–8192 项）

每项恰含唯一 `ticket_id`、`course_id`、`team_id`（初始负责队，须已登记）、
`opened_at`、`summary`、`events`。

- 开单不晚于 `as_of`，相距不超过 730×1440 分钟。
- `summary` 原样消费现有 v1 数字摘要，沿用五字段校验与 single/light/heavy
  档位；工单档位固定，策略只改该档时限。
- `events` 至多 64 项。每项含 `at` 与 `op`：`at` 严格晚于开单且不晚于
  `as_of`，同工单不得有同刻事件；`pause`、`resume`、`close` 不带其他字段，
  `transfer` 还需已登记且不同于当前队的 `team_id`。
- 开单即办理中；办理中才可暂停、暂停中才可恢复；两种状态都可交接或结单，
  **交接不改变暂停状态**，结单后禁止再有事件。
- 输入列表、时段与事件可以乱序（星期位置及时段两端点的位置除外）；事件先逐条
  校验再按时刻排序，状态机按时间顺序复核，因此乱序合法输入与有序输入同结果。

## 核算口径

从开单起累积**有效分钟**。某分钟只有在其**开始时**工单正在办理（非暂停、未
结单），且落在**当时负责队**的服务时段内才计费；时段左闭右开，这一分钟在下一
整分钟时刻计入累计。暂停或非服务时段不计时；最多计到结单时刻或 `as_of`。交接
前后分别用各自队的日历，累计不清零。

在每个整分钟时刻严格按以下顺序处理：

1. 先计入刚结束的一分钟（若有效）；
2. 再应用该时刻的工单事件（暂停/恢复/交接/结单）与生效策略；
3. 最后判断：仍未结单且累计分钟数达到或超过当前档位时限，就记为**首次违约**，
   责任归**处理事件后的当前队**。

由此得到几条关键语义：

- 缩短时限可以在**暂停中或服务时段外**触发违约（当刻没有新增有效分钟也可能
  违约）；同刻结单则不产生新违约。
- 若达到时限的那一分钟恰好在一个事件/策略时刻结束，违约判定延后到该时刻的
  事件与策略应用之后：责任取交接后的当前队，时限取新生效的值。
- 已发生的首次违约**不因结单、调高时限或再交接而撤销或改名**。
- `as_of` 时刻也执行上述判断；本命令不推算将来的截止时间。

## 输出

JSON 对象恰含 `schema_version: 1`、`as_of`、`tickets`、`breaches_by_team`。

- `tickets` 按 `ticket_id` 升序，每项含 `ticket_id`、`tier`、`charged_minutes`
  （完整累计，即使先违约仍计到结单或 `as_of`）、`state`
  （`active`/`paused`/`closed`）、`first_breach`。
- 未违约时 `first_breach` 为 `null`；否则为恰含 `at`、`team_id`、
  `charged_minutes`、`limit_minutes`、`effective_at` 的对象，全部取**首次违约
  当刻**的值（`effective_at` 是当刻适用策略的生效时刻）。
- `breaches_by_team` 按 `team_id` 升序，每项含 `team_id`、`count`，只列有违约
  的队；每张工单只计一次。
- 合法输入重排不改变输出字节（所有列表按业务编号排序，发布统一
  `sort_keys`）。结果一次性新建，不覆盖已有目标（含符号链接）。

## 长跨度服务时段与跳跃正确性

工单跨度可达 730 天、单批 8192 张，逐分钟模拟不可行。实现按每张工单的
「关键时刻」（事件时刻、策略生效时刻、`as_of`）做**区间跳跃**：

- 为每支队预建覆盖整段时间的**逐日服务时段与前缀有效分钟和**。任意半开区间
  `[start,end)` 的有效分钟数由「首日剩余 + 中间整日前缀差 + 末日开头」在
  O(天数对数 + 时段数) 内求出；单日最多 8 个时段，长跨度的连续服务区间被整段
  求和，而不是逐分钟累加。
- 一段 `[cursor, moment)` 内负责队、暂停状态、适用时限都不变。若累计会在段内
  达到时限，用前缀和**二分**定位到哪一天、再在当天时段内定位第
  `limit-charged` 个有效分钟的结束时刻；零服务日表现为前缀和的等值平台，被
  二分自然跳过。因此无论服务时段多长、停服间隙多大，都不会逐分钟扫描。
- **不漏边界**的保证：跳跃只在「队、暂停状态、时限」三者都不变的区间内进行；
  每次交接、暂停/恢复、策略生效都强制成为一个区间端点，端点时刻严格执行
  「先计分钟、再应用事件与策略、最后判违约」的顺序。落在边界时刻结束的那一
  有效分钟不在段内提前判违约，而是交给当刻判断，从而不会漏掉或提前任何策略/
  交接边界。
- 复杂度：每工单 O((事件数 + 同课程策略数) × log 跨度)，与跨度内的分钟数无关；
  日历内存为 O(队伍数 × 跨度天数)，730 天 ×256 队约 19 万天条目。

## 错误

非法输入或文件错误**退出 2**、诊断写 stderr，不留部分结果，不覆盖已有目标
（含符号链接）。包括但不限于：结构/字段不符、非法时刻或公历日期、时段重叠或
越界、编号重复或未登记、开单时无可用策略、事件状态机非法（含结单后事件、
同刻事件、交接未换队）、超 730 天跨度、布尔作整数、重复 JSON 键、非有限值与
超 8 MB 文件。

## 本地复现

### 第 1 条验收场景（单工单三变体）

```sh
PYTHONPATH=src python3 -P -m unittest discover -s tests -p 'test_sla.py' -v
```

`AcceptanceScenarioTests` 覆盖：周二 12:00 降限到 180 当刻累计 180、首次违约记
B；同一时间线把新策略移到 12:30，则 12:30 累计 210 违约、记 A（刚结束的分钟由
B 服务，但责任取交接后的 A）；12:30 同刻结单则无违约、最终仍累计 210。另含
暂停中降限、恰好未达限的 `as_of`、违约后升限不抹去归因。

### 第 2 条：20 CPU 秒预算的长跨度夜间对账

```sh
python3 -P tools/sla_bench.py --directory run/sla-bench
```

它在受限进程**之外**生成 8192 张跨度 104 周的合法 single 工单（两门课各 4096
张，分别采用 12:00 与 12:30 生效版本，A 在提前后的开单日 2024-11-11 整天
停服），再用 `RLIMIT_CPU=20` 运行真实 CLI 单进程从读入到输出，不委托子进程或
服务。脚本先断言 `104×360−180=37260`、旧/新限额 `37500/37440`，再**逐工单**
核对：12:00 版本在累计 37440 时违约记 B、12:30 版本在累计 37470 时违约记 A，
每单最终累计都是 37470；另对 12:30 版本用小批核对同刻结单不违约。

### 第 3 条：独立逐分钟对照

`tests/test_sla.py` 里的 `oracle()` 是一套完全独立的逐分钟参考实现（不复用
`sla.py` 的日历与跳跃逻辑，只共享时间解析约定），80 组随机小工单逐分钟核对
累计、首次违约五字段与最终状态；并确定性覆盖日期替换优先于周表、暂停中的
交接、策略在日界线（00:00）生效、相邻服务时段、非法状态机与输入乱序。
