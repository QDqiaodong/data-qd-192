# 周报联发审查 v1

课程组的公开周报由多份附件组成，同一批收件人会把所有附件放在一起看：有的
附件只给课程合计，有的给结算日合计或少量课程明细。校方希望继续发布这些
精确数字，但不能让收件人单凭这套附件反推出政策点名保留的格子。本命令用
工作量台账的**同一份 v1 快照**在本地审查整套附件：要么生成整包发出，要么
阻止整套发出。只处理教学合成计数，不读作业内容，不读台账内部文件，不改动
任何既有命令，运行只依赖 Python 标准库。

```sh
sequence-digest-release-check --snapshot SNAPSHOT.json \
  --layout LAYOUT.json --output PACKAGE.json
# 或无需安装：
PYTHONPATH=src python3 -P -m sequence_digest.release_cli \
  --snapshot SNAPSHOT.json --layout LAYOUT.json --output PACKAGE.json
```

`SNAPSHOT.json` 是 `sequence-digest-ledger snapshot` 的 stdout 原样重定向；
本命令不读台账内部文件。

## 输入

### 快照

沿用排班入口接收的 v1 快照结构与数值边界：`schema_version` 为 `1`，`head`
是非负整数，`buckets` 至多 8192 个互不重复的 `(course_id, day)` 桶，每桶
`counts` 三档非负整数、非全零，`points` 为分别乘 1、3、6 后之和且不超过
1000000。快照允许包含本次范围以外的桶：仍须通过校验，但不计入附件。

### 版面（LAYOUT）

顶层恰含 `courses`、`days`、`tier`、`protected`、`pages`：

- `courses`：1–256 个课程 ID（仓库 ASCII ID 规则，区分大小写），不重复。
- `days`：1–32 个严格 `YYYY-MM-DD` 的公历结算日，不重复。
- 两者定义完整矩形；**格子**是 `[course_id, day]`，两个合计口径均限于这个
  矩形。只取所选档位的提交数，不按 points 核算。
- `tier`：`single`/`light`/`heavy` 之一。
- `protected`：至少一个格子，不重复；每个格子须在矩形内。
- `pages`：2–8 个附件。每个附件恰含唯一 `page_id` 与三份可为空的列表：
  `cells`（要刊登的单格）、`course_totals`（要刊登的课程合计，课程 ID 表）、
  `day_totals`（要刊登的日期合计，日期表）。所有引用须在矩形内，每份列表
  内部不得重复；**同一数字可在不同附件重复刊登**。

快照没有某桶时该格真实值为零，但不意味着收件人知道它为零。沿用本仓严格
JSON 边界：每份输入 8 MB 上限，拒绝重复键、非有限数、布尔值充当整数与多余
字段。栏目由报表负责人决定：不得偷偷少刊附件、调换范围、隐去合计或扰动数值
来通过审查——版面点名的每一项都按快照原值刊登。

## 联发口径

只审查这次联发带来的精确算术推断。不假定收件人掌握台账、缺桶列表、其他
档位、旧期数字或外部事实。收件人知道矩形和每个格子的公开取值范围：0 到
`floor(1000000/所选档位权重)` 的整数（权重 single/light/heavy 依次为
1、3、6）。除此以外，他们用来反推的约束仅是**全部附件的全部刊登数值**；
重复刊登不产生新约束。一张不同的整数表只要在公开范围内、逐条满足这些单格
值与合计值，就是可能的原表。每个受保护格须各自**至少有两个可能值**，见证
不必由同一张替代表给出。刊登了受保护格本身、某个值为零的公开合计、或多页
合计联合固定了受保护格，都判为可推出。

### 怎样确定整数格可变

以真实表为基点，受保护格 `(a,b)` 能否 ±1 等价于**残量图上的可达性**：

- 每个未刊登格真实值 `< 上限` 时有前向边（课程→日期），`> 0` 时有后向边
  （日期→课程）；已刊登格被收件人固定，两边都没有。
- 未公布合计的行/列是自由节点：合计未公开意味着它既能吸收也能提供任意
  差额，自由节点两两之间可自由中转。
- 给 `(a,b)` 加一，当且仅当存在一条从 b 回到 a 的补偿路径把行/列合计补平；
  减一对称。简单路径不会中途重新经过起点，所以只需在起点第一步排除该格
  自身的反向残量边。
- 行、列合计的约束矩阵是二部图关联矩阵（全幺模），整数表与实数表的可行
  投影一致：不会把实数表上的变化误当整数计数变化，也不会漏报已固定的
  保护格。

两个方向都不可动（或该格本身已被刊登）即判定为可推出。逐格独立判定，每个
方向一次位集宽度优先；256×32 全保护时共 16384 次小规模可达查询。

## 输出

### 允许联发（退出 0）

一次性新建 `PACKAGE.json`（不覆盖已有目标，含符号链接）：

- 顶层恰为 `schema_version: 1`、`tier`、`courses`、`days`、`pages`。
- 每个附件保留 `page_id`；`cells` 每项 `{course_id, day, count}`，
  `course_totals` 每项 `{course_id, count}`，`day_totals` 每项
  `{day, count}`，只列版面点名的信息。
- 不附加保护清单、台账游标、中间诊断或未刊登数值。
- 各列表按身份升序（格子先课程再日期，附件按 `page_id`，课程/日期按身份）；
  重排合法输入不改变文件字节。

### 不允许联发（退出 3）

stderr 返回一行 JSON，列出**全部且仅有**可推出的受保护格，按课程、日期
升序，不输出推得的数值：

```json
{"forced":[["A","2026-11-10"]]}
```

不发布任何附件，不留部分结果。

### 输入或 I/O 不合法（退出 2）

版面、快照或文件读写不合法时退出 2，stderr 说明错误；输出目标已存在（包括
符号链接）也属这一类。失败不发布任何附件，不留部分结果，不覆盖旧文件。

## 合并附件与写出整包之间的失败边界

审查严格分两段：先**合并**全部附件的刊登数值做联发推断，得出「允许」或
「拒绝」结论；只有结论为允许时才**写出**整包。

- 合并阶段发现任一受保护格可推出：退出 3，不创建输出。
- 合并阶段通过：原子新建整包（临时文件 + 链接，目标已存在即失败并清理）。
- 任一阶段输入/输出不合法：退出 2，不留部分结果，不覆盖旧文件。

## 本地复现

### 验收场景：联发固定与放行

`tests/test_release.py::AcceptanceTests` 用台账入口产生真实快照（A、B 两门
课，结算日 x=2026-11-10、y=2026-11-11，single 计数 A=(2,8)、B=(7,13)），
保护 A/x；附件一刊登课程合计 10 和 20，附件二刊登日期合计 9 和 21 外加
B/y=13。每个附件单独给出的数不能固定 A/x（只有课程合计时 A/x 可在
(2,8)↔(3,7) 间变动；只有日期合计与 B/y 时同理），但联发后四个合计加
B/y=13 把 A/x 固定为 2：退出 3 且只报告 `[["A","2026-11-10"]]`。快照完全
不变、只撤去附件二的 B/y 栏目时必须允许联发——例如 A=(3,7)、B=(6,14) 与
原表给出相同的四个合计。手动复现：

```sh
export PYTHONPATH=src
python3 -P -m sequence_digest.ledger_cli apply \
  --store run/ledger.json --source run/batch.json     # 30 条 put 累积上述矩阵
python3 -P -m sequence_digest.ledger_cli snapshot --store run/ledger.json \
  > run/snapshot.json
python3 -P -m sequence_digest.release_cli \
  --snapshot run/snapshot.json --layout run/layout.json --output run/package.json
```

### 受限进程容量验收

```sh
python3 -P tools/release_bench.py --directory run/release-bench
```

在受限进程之外直接生成合法 v1 快照：single 档 256 门课 × 32 个结算日，前
255 门各格 500000、末门各格为零（快照不列该门的桶）。保护全部 8192 格，
一页刊登全部课程合计，另一页刊登全部日期合计，无明细。真实 CLI 在单进程
`RLIMIT_AS=128 MiB`、`RLIMIT_CPU=20` CPU 秒下从读入跑到结束（不把计算转给
子进程或服务）：完整版面须精确拒绝末门的全部 32 格且不误报其他课程；从
第一页撤下末门和首门的课程合计后（其余栏目不变），须在同一限额下发布完整
包——第二次可把首门某日的一个计数移到末门同日，其他正值行仍可在有公布
合计的行日之间成对调整。生成和断言不计入 CLI 限额。
